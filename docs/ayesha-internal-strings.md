# 내부 엔진 문자열 후보와 번역 제외 기준

여기서 '엔진 문자열'은 화면 문구보다 코드·자료구조·리소스 이름일 가능성이 높은 문자열을 뜻한다. 실행 파일 전체가 어떤 단일 엔진/버전으로 구성되었다고 확정하는 문서는 아니다.

## 관찰된 부류

| 부류 | 짧은 예시/패턴 | 조사할 참조 | 기본 처리 |
|---|---|---|---|
| 스크립트 VM 진단 | `weakref`, `nativeclosure`, 슬롯·스택·타입 오류 | VM 오류 처리/로그 호출 | 원문 보존 |
| 그래픽/모델 속성 | `COLLADA`, `Material`, `Shader`, `Shadow` | 파서 키, 렌더링 상태, 객체 생성 | 원문 보존 |
| 런타임 식별자 | `Player`, `Ghost`, `Locked`, `Back` | 호출 문맥, 문자열 비교·등록·검색 | 표시용 사용과 분리 |
| 이벤트·임무 레코드 | `QQ…`, `QN…`, `QC…`, `MM…` | 임무 ID/표시명/설명의 어느 필드인지 | ID는 보존 |
| 준비·예약 레코드 | `Main Prep`, `DLC Frame`, `Dummy`, `Unused` | 활성 여부, 예약 슬롯 | 원문 보존 |
| 모델·배경·효과 리소스 | `Field Map Enemy`, `Map Effect`, 모델 변형 이름 | 리소스 테이블과 파일 조회 | 원문 보존 |
| 전투 내부 레코드 | 역할명 + `Skill 1`, `AC Defense`, `Super Move` | 내부명과 실제 스킬 표시명이 나란히 있는지 | 표시 필드만 번역 |

VM 용어는 Squirrel 계열 진단을 시사하고 COLLADA 용어는 모델/그래픽 처리 부분을 시사한다. 정확한 엔진 버전, 모든 호출 경로, 모든 항목의 비표시 여부까지 입증한 것은 아니다.

## 공통 영어 제외 — 사용자가 지정한 정책

**아직 미반영인 후보**의 영어 바이트열이 해제된 일본판 세그먼트에도 존재하면 추가 패치 대상에서 제외한다. 이미 정상 작동한 번역을 되돌리는 정책은 아니다.

이번 재검사는 text/rodata/data를 각각 검색했고 비교 형태는 `english_bytes + NUL`이었다. 앞쪽 NUL은 강제하지 않아 접미부 공유 문자열도 공통으로 잡았다. 압축 파일 전체를 직접 비교하거나 다른 세그먼트를 이어 붙인 가짜 경계에서 검색하지 않는다.

공통 영어는 내부 식별자의 유력한 단서지만 확정 증거가 아니다. 일본판에도 영어 UI, 곡 제목, 다른 로케일 테이블이 들어갈 수 있다. 반대로 일본판에 없는 영어라고 모두 화면 문구인 것도 아니다. 이 규칙은 사용자 요청에 따른 보수적 제외 정책이다.

## 마지막 스캔 집계

- 스캔 목록: 7,327개. 게임 전체 텍스트의 완전한 목록이라는 의미는 아니다.
- 6,563개 패치가 반영한 스캔 항목: 6,264개. 누적 번역 수와 차이 나는 299개는 해당 스캔 이전 기준에 속한다.
- 미반영: 1,063개. 정적 분석상 내부 레코드/리소스 642개, 엔진 진단/키 421개로 분류했다.
- 그중 일본판에도 있는 공통 영어: 1,006개.
- 공통 영어 제외 후: 57개. 이벤트/임무 표식 15개, 스토리 준비 레코드 31개, DLC 예약 슬롯 9개, 미사용 자리표시자 2개.
- 이 재검사에서는 추가 표시 문구를 확인하지 못해 새 패치를 만들지 않았다.

이 숫자는 현재 분류 결과이며 '내부 1,063개 전부가 어떤 화면에도 절대 표시되지 않는다'는 증명이 아니다. 화면 증거가 나오면 해당 참조만 재검토한다. 특히 과거 작업 중 이름만으로 분류했다가 실제 UI 테이블을 확인해 수정한 사례가 있었다.

## 다음 분해에서 지킬 판단 순서

1. 사용자에게 보이는 화면 또는 표시 함수/로케일 레코드의 증거가 있는가?
2. 같은 주소를 내부 키와 UI가 함께 쓰는가?
3. 일본판 공통 영어 제외 정책에 걸리는가?
4. 한글 대응의 근거가 테이블/일본어/PC 자료에 있는가?
5. 바꿀 참조를 주소별로 제한할 수 있는가?

단어가 짧다거나 영어라는 이유만으로 번역하지 않는다. `Name`, `Quality`, `Default` 같은 단어는 표시용 참조만 바꾸면 되지만, 문자열 저장 영역을 통째로 바꾸면 내부 조회에도 영향을 줄 수 있다. 반대로 이러한 단어를 영구 블랙리스트로 만들면 정상 메뉴가 누락된다.

추천 분류 상태는 `display_confirmed`, `shared_english_excluded`, `internal_candidate`, `ambiguous`, `applied`이다. 근거와 검사 방법을 상태와 함께 저장한다. 공개 저장소에는 전체 추출 문자열 대신 분류 규칙과 집계만 올린다.
