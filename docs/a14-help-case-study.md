# A14 도움말 G1T 사례 기록

## 관찰

- 제공된 `a14_dictionary_EN.PSSG`에는 `a14_dict_mons*.g1t` 계열 70개만 들어 있었습니다.
- 도움말 `a14_dict_help*.g1t` 81개는 PSSG 내부가 아니라 인접한 `a14_dictionary/` 폴더에 개별 파일로 존재했습니다.
- 도움말 G1T는 `GT1G` 형식이며 Switch 플랫폼 값은 `0x10`이었습니다.

## 실패했던 접근

몬스터 도감용 PSSG의 LIBRARY에 도움말 BINARYOBJECT 81개를 새로 추가하고 TYPEINFO 개수를 갱신했습니다. 자체 파서에서는 다음 검증을 통과했습니다.

- PSSG 노드 경계
- 선언된 데이터 크기
- 객체 이름 중복
- 포함된 G1T 해시

하지만 게임은 결과를 읽지 못했습니다. 원인은 PSSG 문법이 아니라 **게임이 해당 PSSG에 기대하는 의미적 리소스 집합을 바꾼 것**이었습니다.

## 정상 동작한 해결책

1. 몬스터 도감 PSSG를 원본 그대로 유지했습니다.
2. 번역한 도움말 이미지를 원본 도움말 G1T와 동일한 해상도와 BC1 데이터 길이로 재압축했습니다.
3. 각 G1T의 Switch 플랫폼 값을 `0x10`으로 설정했습니다.
4. 파일명과 상대 경로를 보존해 다음처럼 배치했습니다.

```text
romfs/Res/NX/winxls_EN/
├─ a14_dictionary_EN.PSSG          # 원본 유지
└─ a14_dictionary/
   ├─ a14_dict_help000.g1t
   ├─ ...
   └─ a14_dict_help086.g1t
```

번호는 연속적이지 않을 수 있으므로 임의로 빈 번호를 만들지 않고 원본 파일 목록을 그대로 사용해야 합니다.

## 일반화된 교훈

- “PSSG 내부 G1T를 바꾼다”와 “개별 G1T를 PSSG에 새로 넣는다”는 완전히 다른 작업입니다.
- 컨테이너가 파싱된다고 해서 게임이 그 안의 임의 객체를 받아들이는 것은 아닙니다.
- 가장 안전한 패치는 원본 외부 구조와 크기를 유지한 in-place 교체입니다.
- 서로 다른 플랫폼의 PSSG를 통째로 재직렬화하기보다 Switch 원본 바이트를 유지하고 호환되는 G1T 블록만 교체하는 편이 안전합니다.
